# Agent task: isosurface-density (AG3)

Status: Implemented; desktop WebGL and WebGPU verified, no phone
Owner: Engine/toolchain
Last reviewed: 2026-11-17

## Source requirement

Work package AG3 of
[Techniques from Abyssal Garden](../abyssal-garden-techniques/plan.md),
taken up on the owner's request of 2026-11-17: floating pieces removed
before meshing an isosurface, and a density volume computed on the GPU
through `ZhudaComputePass` with its JavaScript fallback, read back once at
load.

## Goal

`createZhudaIsosurfaceMesh({ ..., removeFloating: true })` meshes only the
body connected to an anchor (the box's floor by default), so loose specks of
rock do not float; `computeZhudaDensityVolume` fills the mesher's grid with a
GLSL density on WebGPU (or the same density in JavaScript elsewhere), with
cancellation, a time limit, failure and disposal handled, and the mesher
meshes that volume.

## Invariants

- Meshing stays on the CPU; the 2 000 000-vertex refusal and
  `splitZhudaMesh` stay.
- Without the new options the mesher returns the same mesh as before.
- The GPU volume and the JavaScript volume agree within float tolerance;
  the GPU result is checked against the JavaScript density at sample points
  before it is used, so a shader that failed to compile cannot pass as rock.
- Every load: an `AbortSignal`, a time limit, the pass disposed on every
  path, no result returned after cancellation.

## Dependencies

- `packages/core/procedural/Isosurface.ts` (surface nets),
  `packages/core/runtime3d/ComputePass.ts` (compute and its fallback).

## Scope

### Engine

- `Isosurface.ts`: `removeFloating` (`true`, or `{ anchor: 'floor' |
'largest' | [x, y, z] }`), `volume` (a precomputed grid instead of
  sampling `distance`), `zhudaIsosurfaceGrid`, `zhudaVolumeDistance`
  (trilinear).
- `runtime3d/ComputePass.ts`: dispatches of more than 2 097 152 indices in
  rows (found while doing this task; see the verification record).
- `runtime3d/DensityVolume.ts` (new): `computeZhudaDensityVolume`,
  `validateZhudaDensitySpec`.
- Declarations regenerated by the build; tests; a browser check
  (`scripts/verify-density-volume.mjs`, `tests/fixtures/density-volume.ts`);
  `docs/procedural-assets.md`.

### Consumer or adapter

A consumer writes its density in GLSL and in JavaScript (the fallback and
the reference), and decides what a removed piece means for its game.

## Non-goals

- Meshing on the GPU; marching cubes; caves seen from inside (authored
  meshes, as `AGENTS.md` says).
- A density language shared between GLSL and JavaScript: the consumer
  writes both, and the engine checks they agree.

## Acceptance checks

1. Geometry fixtures: a slab with three loose specks meshes as one closed
   piece with `removeFloating`, four pieces without; `'largest'` and a point
   anchor; a mesh from a volume equals the mesh from the same field sampled.
2. A browser check on WebGPU and WebGL: the GPU volume equals the
   JavaScript volume within tolerance (WebGL: the fallback, `backend: 'cpu'`);
   a load cancelled before and during, timed out, failed (a density that
   throws; a GPU density that disagrees), disposed; 30 load and release
   cycles leave no resource behind.
3. `npm run verify`, lint, format, `git diff --check`.
