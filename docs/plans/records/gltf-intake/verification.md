## Measured: the embedded-picture path

`big-picture.glb` holds one 2048 by 2048 PNG of 10.4 MB. Five rounds each,
alternating; the script asks the page for its JavaScript heap
(`Runtime.getHeapUsage`) every few milliseconds while a load runs and after a
forced collection when it ends. Times include fetching the file over loopback.

| Median of 5, last run | LayaAir `glTFResource._parseglb` + `create()` | Engine `ZhudaModelLibrary.instantiate` |
| --- | --- | --- |
| Time, WebGL | 396.1 ms | 76.5 ms |
| Time, WebGPU | 385.5 ms | 49.4 ms |
| Sampled heap peak above the start, WebGL | 292.7 MB | 0.14 MB |
| Sampled heap peak above the start, WebGPU | 292.7 MB | 0.23 MB |
| Heap kept while the model lives (after collection), WebGL / WebGPU | 34 / 28 KB | 20 / 5 KB |

The peak comes from LayaAir's `Base64Tool.encode`, which builds the data URL
one character at a time (about 14 million concatenations for this picture).
Neither path keeps it: the retained heap is the same. The heap is sampled
between the page's tasks, so a peak inside one synchronous task could be
missed; these are lower bounds of the peak. The decoded picture's own memory
(outside the JavaScript heap) and GPU memory are not measured. Across three
runs per backend the medians ranged 344–450 ms against 49–95 ms, and the
sampled peaks 292.7 MB against 0.12–0.24 MB.

## Lifecycle and failure cases

Unit tests (`tests/gltf-intake.test.mjs`) cover:

- Meshopt: KHR name with COLOR and OCTAHEDRAL filters decodes to the
  encoder's bytes (positions and texture coordinates exact, colours within
  one 8-bit step); COLOR under the EXT name, COLOR with a 12-byte stride, both
  names on one view and an unknown filter are refused; `DECODER_REQUIRED` is
  an error when required and makes the file `degraded` when optional.
- Dequantizing: values through the node transform match the float file
  within 2e-5 m; normalized signed values clamp at -1; integer values stay
  whole; sparse values are applied; a `.gltf` with data-URI buffers comes out
  as a GLB; the embedded picture's bytes survive; node transforms are
  unchanged; `KHR_mesh_quantization` leaves the declarations; Meshopt then the
  pass gives the same floats as the pass alone. Refused: an unsigned 32-bit
  POSITION (also `INVALID_DOCUMENT` in the report), a wrong TEXCOORD type,
  external buffers, an accessor reading past its view, falling sparse
  indices, an output over budget, an invalid budget.
- WebP/AVIF: the source order (AVIF, WebP, fallback) for each device answer;
  `IMAGE_DECODE_UNAVAILABLE` as error without a fallback and as a degrading
  warning with one; `IMAGE_DECODE_UNCHECKED` without a device answer; the
  inventory's WebP/AVIF images; a resource refuses a texture with nothing
  decodable before loading; embedded pictures reach the Laya loader as a Blob
  URL with their MIME type and bytes, revoked after a successful and after a
  failed load; the probe answers once and says no in Node.
- Lights: file values; six invalid lights each `INVALID_LIGHT` (status
  `degraded`); the mapping (lux/π, colour encoding inverted by LayaAir's own
  decode, equality with glTF's windowed falloff at half the range; within
  30 % from 0.25 to 0.9 of the range without a file range; 0.63 at a quarter
  and 2.04 at three quarters with one); spot cone; zero intensity; invalid
  scales.
- Cameras and extras: frozen copies, the inventory's camera/light indices,
  unnamed nodes, four invalid cameras, `INVALID_CAMERA`, a LayaAir camera aimed
  (perspective, orthographic, infinite far plane).
- `ZhudaModelLibrary` with a stand-in LayaAir: the parser never sees an integer
  vertex attribute; extras and the camera on each copy's own nodes; lights
  only when asked, on their nodes, scaled; an invalid scale refused; in Node
  the WebP file loads its fallback (`degraded`) and the WebP-only file is
  refused with `IMAGE_DECODE_UNAVAILABLE`; every provider lease released.

## Limits and decision

- Phones, mini-game hosts, Safari and Firefox: not run. AVIF decoding in
  particular varies by device; the probe decides per page, the fallback rule
  is unit-tested only (desktop Chrome decodes both formats).
- Dequantizing raises GPU vertex memory back to float; GPU memory not measured.
- An embedded picture's texture keeps a revoked Blob URL as its LayaAir URL, so
  LayaAir cannot fetch it again by URL (the data URL allowed that). Whether
  anything needs that, such as recovery from a lost GPU context, was not tested.
- Light units: the draw shows the engine makes the lights the documented
  mapping describes, on the right nodes and directions. It does not show the
  mapping matches three.js or a DCC render; LayaAir's falloff is not the
  inverse square, and with a file range the two differ by up to about 2x
  between a quarter and three quarters of the range.
- No light casts a shadow from the file; multiple scenes are not built
  (LayaAir builds the default scene).
- All fixtures are generated in code; no seller or Blender-exported file was
  loaded.
- WP4 items not done: `EXT_mesh_gpu_instancing`, texCoord 1 for AO/lightmap
  slots, Meshopt `useWorkers`.

Decision: **Implemented within scope**. Desktop WebGL and WebGPU verified; the
missing device and browser checks keep it from Accepted.
