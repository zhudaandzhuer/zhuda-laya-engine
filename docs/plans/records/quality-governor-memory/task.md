# Agent task: quality-governor-memory (AG2)

Status: Implemented; desktop WebGL and WebGPU verified, no phone
Owner: Engine/toolchain
Last reviewed: 2026-11-17

## Source requirement

Work package AG2 of
[Techniques from Abyssal Garden](../abyssal-garden-techniques/plan.md),
taken up on the owner's request of 2026-11-17 to finish the plans waiting
list: a draw-distance rung, GPU time, memory between visits, a load-crash
fallback and a warm start for the quality governor.

## Goal

A game can hand the governor a GPU frame time and get a level held inside a
band; walk a ladder that lowers a draw-distance `detail` between render
scales; start the next visit at the level it settled on, one lower after a
load that never reached its first frame; and settle the level behind a start
screen before play.

## Invariants

- `ZhudaQualityGovernor` stays pure: it is fed frame times from the game's
  clock (`ZhudaRuntimeSession` / `ZhudaLayeredClock`) and makes no timer,
  listener or store of its own.
- Without GPU times the governor decides exactly as before (CPU rule), and
  says which rule decided (`basis`). Where a browser gives no GPU time
  (WebGL without `EXT_disjoint_timer_query_webgl2`) it is absent, never 0.
- `zhudaQualitySteps()` with no new option returns the same rungs (look,
  render scale) as before; every rung now carries `detail` (1 unless the
  ladder asks for detail rungs).
- Memory and sentinel live only in a storage the consumer passes; a storage
  that throws, is empty, holds another version or another ladder length
  starts from the default.
- `detail` is data: the engine does not decide which distances a scene
  scales.

## Scope

### Engine

- `QualityGovernor.ts`: `ZhudaQualityStep.detail`; `zhudaQualitySteps`
  options `details` (rungs below 1, from the largest) and `detailAt` (the
  render scale after which they come; default the middle of `scales`, as in
  Abyssal Garden: pixels to a middle size, then detail, then the rest of the
  pixels, then the look levels); governor `sample(frameMs, gpuMs?)`,
  `gpuBand` (default 0.84..1.16 of the budget), `basis`, `warm(on)` with
  `warmWindow` and `warmCalmFactor`.
- `QualityMemory.ts` (new): `ZhudaQualityMemory` (read, write, the load
  sentinel `beginLoad` / `endLoad`, `startLevel`), `ZhudaQualityStorage`.
- `EffectBudget.ts`: `ZhudaRuntimeProfiler.takeGpuMs()`, the newest GPU time
  resolved since the last call (a frame's time arrives a frame or more late).
- `SceneLook.ts`: `setStep` checks `detail`.
- Tests, a draw check (`scripts/verify-quality-governor.mjs` with
  `tests/fixtures/quality-governor.ts`), declarations regenerated by the
  build, `docs/film-scenes.md`, `docs/quality-route.md`, the plan's progress
  table and its `docs/plans/README.md` row.

### Consumer or adapter

The consumer passes its storage (for example `localStorage`), names the key,
calls `beginLoad` before its heavy build and `endLoad` on its first frame or
when the page is hidden, and multiplies `detail` into its own distances.

## Non-goals

- Applying `detail` inside the engine (grass, culling, fog): the scene owns
  its distances.
- A timer or a page listener in the engine.
- GPU time on WebGL through anything but the existing profiler (timer query
  where the browser exposes it).
- Tuning the default rungs: they stay a proposal until a phone measures them.

## Acceptance checks

1. Unit tests: GPU band (down above, up after a calm stretch below, stays
   inside), CPU rule unchanged without GPU times, descent order of a ladder
   with detail rungs (default and `detailAt`), storage that throws, empty,
   corrupt, another version and another ladder, the sentinel lowering the
   next start one level, warm start settling within a shorter span.
2. A draw on WebGL and on WebGPU (`scripts/verify-quality-governor.mjs`):
   frames forced slow walk the ladder down in its order, each rung applied
   to a look and to the scene's far row through `detail`; the far row is
   gone at the lowest detail and back at the top; on WebGPU GPU times reach
   the governor and it decides on them.
3. `npm run verify`, lint, format, `git diff --check`.
