## 最值得先知道的五件事

1. **衣服的顏色有問題，量測量不到。** 洋裝臀部兩側、長褲臀部後面有深灰色不規則斑塊，所有開口有一圈深色鋸齒邊。它們在零件檔的頂點顏色裡，軟體繪製和真顯卡上都一樣；兩種穿模量測只看形狀。（B1；雲端在 `790f5e95` 改成單一顏色，真顯卡重拍確認斑塊和深色邊不見了，剩下的小殘留寫在 B1 的筆記。）
2. **幀率的瓶頸是像素，不是三角形。** 一個角色 17,327 個三角形（實際每幀畫 96,344 個、69 次繪製），M4 上 1280×720 很輕鬆，1920×1080 就掉到 41 到 46。先看場景的畫面設定和像素比上限，再談合併網格。（C1）
3. **工具做的衣服交給建模軟體會壞兩件事。** 雙面的布會掉一面；「不穿模」靠的資訊在工具的清單和遮罩裡，不在檔裡，來回一趟就要重量。（A2）
4. **有三個測試只在雲端的機器上成立。** 其中割草的勝率測試是因為同一個種子在不同機器上會跑出不同的一局。已修。（A1）
5. **用真的 Chrome 開，每一款都有一個主控台錯誤**：`favicon.ico` 404。（C1、C4；量完之後已在九款的頁面各加一行空圖示修掉，上面的量測紀錄是修之前的。）

## D6：Spine

這台 Mac 沒有 Spine 編輯器（`/Applications` 和 `~/Applications` 都沒有），所以「用編輯器匯出一個角色」和「在編輯器打開代理人產出的工程檔」都做不了。

手邊有的是代理人工具做的檔，不是編輯器匯出的：`ZhudaGameCenter/engines/zhuda-spine2D`（2.7.0）會產生 Spine 4.2 的骨架 JSON、圖集和圖，例如 `examples/whitemodels/heroine/build/001/heroine.json`、`heroine.atlas`、`heroine.png`。它們在 spine-webgl 4.2 的原生 runtime 裡播得起來（該工具包的 README 這樣寫；我沒有重跑）。能不能在編輯器打開，沒有人試過。

## F1：圖像流程

擁有者的圖都是從這台 Mac 指揮公司的 Windows 主機（RTX 3060）做的，有兩條：

| | 雲端模型（`winbdl img`） | 本機模型（`winbdl qimage`） |
| --- | --- | --- |
| 模型 | gpt-image-2.6 | Qwen-Image 2.1（ComfyUI） |
| 要不要額度 | 要 | 不要 |
| 尺寸 | 面積固定約 157 萬像素，只能選比例：1:1 是 1254×1254，3:2 是 1536×1024，2:3 是 1024×1536，16:9 是 1672×941；最寬 3:1。要別的大小就生完再縮 | 1024×1024 到 2048×2048 |
| 透明背景 | 可以（每張可以指定） | 這份紀錄裡沒寫 |
| 無縫拼接 | 不能直接指定。地面貼圖是生 1254×1254 的原圖，再用 `commonAssets/textures/tools/process.py` 後製成 1024 的無縫方塊 | 同左，要後製 |
| 參考圖 | 可以（角色一致） | 可以，最多 3 張（角色和姿勢） |
| 一張多久 | 生成前工具會列出每張的預估秒數；可以平行生 | 1024×1024 約 26 到 28 秒，2048×2048 約 60 秒，帶 2 到 3 張參考圖 42 到 132 秒 |
| 文字 | 沒指定時會自動加「不要文字、不要浮水印」 | 繁體中文招牌字寫得對 |

另外同一台主機可以把圖轉成帶 UV、顏色、金屬粗糙、法線、遮蔽貼圖的 3D 模型（約 2 到 7 分鐘一件）。

以上是照操作手冊（技能 `zhuda-windows`）整理的，這一輪沒有實際生圖。每次生圖要花額度或佔用那台主機，所以要的圖請列清單，由擁有者說做哪些。
